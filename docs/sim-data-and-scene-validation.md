# Simulation Data and Scene Validation

This document defines the simulation-side contract for the A7 task scene. It
keeps simulation and real capture semantically aligned while keeping all
simulation topics below `/sim`.

## Unified Camera Contract

Each camera publishes the same four topic suffixes:

```text
<camera_namespace>/color/image_raw                    sensor_msgs/Image, rgb8, 640x480
<camera_namespace>/aligned_depth_to_color/image_raw   sensor_msgs/Image, 16UC1, 640x480, millimetres
<camera_namespace>/color/camera_info                  sensor_msgs/CameraInfo
<camera_namespace>/depth/camera_info                  sensor_msgs/CameraInfo
```

The simulation camera namespace is `/sim/camera`:

```text
/sim/camera/camera       head_d435i
/sim/camera/left_wrist   left_wrist_d405
/sim/camera/right_wrist  right_wrist_d405
```

The real D435i default remains `/camera/camera`. The capture recorder uses
`REALSENSE_NAMESPACE`, `ROBOT_STATE_NAMESPACE`, `TELEOP_NAMESPACE`, and
`SOURCE_DOMAIN` so the bag schema does not depend on a hard-coded machine.

## Start Simulation

### USB-C insertion teleoperation scene

This scene combines the calibrated A7, two L10 hands, calibrated cameras,
table, laptop, receptacle and a free movable USB-C plug. Build and launch it
with:

```bash
cd "$(git rev-parse --show-toplevel)"
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
MPC_PYTHON=/home/ilex/miniforge3/envs/mpc_env/bin/python \
  bash scripts/launch_a7_usb_c_insertion_scene.sh
```

The scene file is generated at
`assets/robots/linker_platform/sensorized/a7_l10_usb_c_insertion.mjcf.xml`.
It is simulation-only and never starts `lbot_driver`. Arm commands use the
same mapped radians topic as the real path; L10 hand commands use the same
`[0,255]` ROS2 `JointState` contract. The plug is currently a MuJoCo
`freejoint`; a grasp constraint/controller must be added before claiming a
successful hand-held insertion.

With a local desktop available on iLeX24:

```bash
cd "$(git rev-parse --show-toplevel)"
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
export MUJOCO_GL=glfw
ros2 launch sim_robot_driver sim_teleop.launch.py \
  model_path:=$PWD/assets/robots/linker_platform/sensorized/a7_l10_usb_c_insertion.mjcf.xml \
  render:=true keyboard:=true
```

Without a display, use `MUJOCO_GL=egl` and `render:=false`; camera topics still
publish:

```bash
export MUJOCO_GL=egl
ros2 launch sim_robot_driver sim_teleop.launch.py \
  model_path:=$PWD/assets/robots/linker_platform/sensorized/a7_l10_usb_c_insertion.mjcf.xml \
  render:=false keyboard:=false
```

The launch is simulation-only. It never starts `lbot_driver` and does not call
the hardware SDK.

## Record Simulation Data

The same recorder used for real data can record simulation by changing only
the source namespaces:

```bash
SOURCE_DOMAIN=sim \
ROBOT_STATE_NAMESPACE=/sim/robot1 \
REALSENSE_NAMESPACE=/sim/camera/camera \
SIM_CAMERA_NAMESPACES=/sim/camera/left_wrist,/sim/camera/right_wrist \
TELEOP_CAPTURE_DURATION_S=10 \
bash scripts/record_episode.sh
```

The capture manifest records `source_domain`, all camera namespaces, recorded
field names, units, and timestamp policy. It is an `episode/v1` capture
manifest, not a `teleop_episode/v0.1` canonical manifest. Simulation timestamps use the ROS2
clock generated by the mirror node; real timestamps remain the driver and
camera ROS2 header stamps.

## Scene Validation

Validate the generated USB-C scene without ROS2 or hardware:

```bash
/home/ilex/miniforge3/envs/mpc_env/bin/python -B \
  tools/validate_connector_insertion_scene.py \
  --scene assets/robots/linker_platform/sensorized/a7_l10_usb_c_insertion.mjcf.xml \
  --require-named-contract --check-collisions --check-success-geometry
```

This checks the scene contract only. It is not evidence of grasp, insertion
success, force fidelity, or a real-robot safety claim.
