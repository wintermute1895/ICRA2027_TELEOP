1.数据采集的启动方式：在对应环境和代码目录下开三个终端。一个终端运行：
```bash
bash scripts/stop_capture_session.sh

  bash scripts/start_capture_session.sh \
    --config=config/capture_session.env \
    --real \
    --physical-estop-ready \
    --confirm=I_UNDERSTAND_REAL_ROBOT
```
另外两个终端分别用来进入tmux会话和停止tmux会话
```bash
tmux attach -t teleop_capture
```

```bash
bash scripts/stop_capture_session.sh
```


2.数据的保存位置：
配置文件在config/capture_session.env，路径的顺序是
```bash
  路径由 scripts/start_capture_session.sh:308 决定：

  RUN_ROOT="${RUNEVIDENCE_ROOT:-$ROOT_DIR/evidence/teleop}"
  [[ -n "$DATA_ROOT" ]] && RUN_ROOT="$DATA_ROOT"

  优先级是：

  1. 命令行 --data-root=...
  2. 配置文件中的 CAPTURE_DATA_ROOT
  3. 环境变量 RUNEVIDENCE_ROOT
  4. 默认路径 $ROOT_DIR/evidence/teleop
```

5.操作员标注方式:
```bash
  实时双人标注已接入采集会话：

  - 新增 tools/audit_event_recorder.py
  - 启动器自动创建 annotate tmux 窗口
  - 审计员数字键无需 Enter，立即生效：

    1 approach、2 align、3 short_insert、4 correction start/end、5 stalled、6 recovery、7target_lost、8 retreat、9 success、0 failure

  - 每条事件记录：
      - ROS 时间戳
      - monotonic 时间戳
      - wall-clock 时间戳
      - episode ID
      - auditor ID
      - sequence
      - 事件类型和 payload

  - 事件同时写入：
      - /teleop/events
      - artifacts/audit_events.jsonl

  - 只有当前 episode 正在录制时才接受标注，避免写入上一条数据。
  - 导出器和 canonical 转换器现在会保留这些事件到 streams/events.jsonl。

  启动后进入审计窗口：

  tmux select-window -t teleop_capture:annotate

  审计员 ID 可以配置：

  CAPTURE_AUDITOR_ID=auditor_01

  或：

  bash scripts/start_capture_session.sh --auditor-id=auditor_01 ...
```
